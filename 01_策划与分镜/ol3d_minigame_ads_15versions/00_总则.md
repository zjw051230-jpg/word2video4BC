# T20260812-144226｜ol3d_minigame_ads_15versions 总则

## 批次定位

本批次是秋季 OL3D 原资产的买量小游戏策划，不是 SLG 大地图、宏大战略或写实军事片。五个玩法企划各自有三种真正不同的操作版本，共 V001–V015；每条成片目标 40–50 秒，按约 4 秒连续片段展开，镜头数量由叙事需要决定，本批次统一采用 11 镜头约 44 秒，方便后续逐镜验收。

旧的“买量版_10情节并行”、四版连续性返工和 redo 目录均为历史交付：本批次不得读取其提示词、关键帧、远端任务、状态、输出或粗剪来替代本版文件，也不得覆盖、混剪。

|D 重甲诱捕|用障碍、陷阱和炮火处理重盾敌|V010落石连锁；V011先拆盾后下陷阱；V012错位陷阱补救|
|E 核心一格|核心临界时维修、分队或诱敌反击|V013一格护核；V014分队救火；V015假撤退反击|

每案的三版共享一个可识别的故事核心和秋季 OL3D 语义资产，但必须改变玩法表达、操作顺序、节奏、镜头调度、反转或奖励展示；不能把同一提示词换编号。

## 统一视觉与可读性

- 秋季 OL3D 背景母版、角色设定页、建筑设施页、地形页和特效图集是唯一视觉权威。入口在棋盘上方，核心在下方，近距离斜俯视让局部棋盘、道路、目标、角色、设施、玩家操作和即时反馈同视野清楚可读。
- 首镜建立必要局部棋盘后维持相近镜位；禁止远景总览、航拍、缩小棋盘、主体过小、SLG 大地图、宏大战略、写实军事和科幻漂移。
- HUD 只允许无文字色块、方向短闪和受损闪烁作为状态提示；禁止可读数字、文字、按钮、标签、血条、字幕、Logo、水印、手机平台控件、horizontal banding、scanline、glitch。
- 参考视频 01/02 只迁移斜俯视镜头运动、单位行进呼吸、操作后停顿和剪辑节奏；不得迁移人物、建筑、雪地、颜色、UI、字幕、水印、Logo或声音身份。
- 每镜只有一个主要玩家输入和一个立即机械反馈；后果要在下一镜首帧继续可见。中文旁白只解释画面中可见的决定与后果，external_tts 在本阶段保持阻塞。

## 当前阶段与后续门禁

本轮只写总则、版本隔离、中文剧情长分镜和 production_plan.json。不得生成关键帧、视频提示词、上传、提交、监控、拉回或粗剪。后续必须逐关执行：

1. 关键帧 Chat 先验收首镜、操作峰值、后果态和末镜；过远、操作与反馈不在同视野、棋盘断裂或身份漂移即退回。
2. 提示词 Chat 每版只能在本版目录补写独立提示词和审查记录；未通过关键帧不得写可提交提示词。
3. 执行 Chat 每镜重新上传本版需要的原资产并保存真实回执，建立本版 asset_id 到 provider payload 的逐项映射；本地路径不算使用素材。
4. 本版全部关键帧和提示词审查通过后，11 个镜头可并行提交，但每镜使用独立任务 ID Vxxx-R01…Vxxx-R11；不得引用另一版本媒体。
5. 绑定 120 秒 heartbeat；本版所有镜头终态后才统一拉回本版 output 目录。逐镜 ffprobe、五帧、资产一致性、连续性和禁止项验收，失败只允许本版单镜送修；身份漂移或条纹问题累计两镜先暂停本版送修并回查上传映射。
6. 所有可用镜头通过后才创建本版 edit/EDL/rough_cut.mp4；external_tts 未解除时不得标记最终交付。
